A useful inventory manager.

The first release should make everyday roll management fast, readable and trustworthy. Keep the existing shared inventory contract; build the interface around physical rolls.

First release implemented · 15 October 2026

The shared-mode Studio workspace now implements phases 1 and 2: right-side spool illustrations, four AMS cards, a physical-roll list, filters/search/sort, a detail panel, local add/edit, measured or estimated stock, assignment with displacement or swap, archive/restore, and guarded Undo. Brand, polymer and slicing profile remain independent. Local editing does not require cloud login.

The companion Python adapter carries exact nullable gram strings, source/date/evidence, revisions and local capabilities. Private write-ahead transactions preserve before/after history, retry identities and crash recovery; Undo rejects newer changes. Read-only background refresh preserves drafts. No automatic consumption deduction is included.

Validation: 85 Python checks passed and one private-log check skipped; both focused C++ tests, the normal TypeScript build, a dedicated stricter inventory configuration, and scoped ESLint passed. Browser checks exercised forms, concurrent edits, outage recovery, focus containment/return, dark/light palettes, 375–1440px layouts and a 1,000-roll fixture. The installed WebKitGTK workspace was inspected with the live inventory; exact capacities, balances, physical IDs and locations were preserved. Follow-up on15 October adds drag/drop swaps and Storage moves plus passive RFID location updates for linked Bambu spool UUIDs. Unknown tags are explicitly associated once with an existing roll or a separate new record; scans do not reset grams.17 RFID accounting cases and fresh-frame C++ tests cover partial reads, removals and restart-safe deduplication. Real tag insertion/read and native dragging remain follow-up qualifications. Bulk workflows, import/export, receipt/replacement and print planning remain later phases. The interactive concept below continues to use isolated sample data.

What the current screen gets wrong

  • Brand and series grouping dominates the hierarchy. Physical identity, amount and location are hard to scan.
  • Long imported notes expose identity markers and accounting prose in every row. Useful stock information loses prominence.
  • Four AMS slots are not the primary navigation surface. Assigning and swapping rolls is hidden behind printer and preset workflows.
  • The React page still gates editing on cloud login even when the C++ layer supports the shared local backend. A local inventory should remain usable when the cloud is unavailable.
  • The native spool schema uses numeric defaults and the list falls back to weight × rounded percentage. Unknown, zero and estimated stock need distinct representations through every layer.
  • Cloud labels remain on acknowledgements that now mean a local transaction succeeded. Saving inventory and Bambu connectivity require separate status.
  • Archive/history are not exposed as useful views. The UI still says delete even though shared mode preserves the historical record.

Audit entry points: FilamentManagerPage.tsx, SpoolTable.tsx, AddEditDialog.tsx, CloudBadge.tsx, types.ts, FilamentManagerVM.cpp and the shared inventory adapter.

Visual direction

Clear hierarchy

Four AMS slot cards at the top. Stored rolls directly below. A contextual detail panel at the right, stacked on smaller windows.

Readable, compact rows

Color spool, user-friendly name, polymer/finish, stock, evidence and location. Put IDs in secondary text and technical metadata in an expandable section.

Quiet, useful color

Graphite surfaces, crisp text, soft borders and a restrained mint accent. Filament colors identify rolls. Amber flags a specific action such as missing material or low stock.

Keep Studio's light/dark theme choice and translate the new tokens into both palettes. Use legible 16px body and 14px supporting text, tabular stock numbers, 44px minimum action targets and visible keyboard focus. Offer comfortable/compact density and remember filters, sort and selection.

Shared spool illustration: refine the widget's familiar three-spoke, three-quarter-view roll with layered flanges, a defined hub and subtle filament windings. Use the same visual design across Studio and the widget. Keep small-size readability and do not imply a measured amount through decorative coil thickness.

Daily workflows

  1. Add a roll: choose new/unopened or already opened; enter a name/color, original net capacity and known material. Brand and slicer profile are optional, independent fields. A new unopened balance is nominal, never labelled weighed. Opened stock can be entered in grams, estimated percent with known capacity, or left unknown.
  2. Assign a slot: choose an existing physical roll, then the destination. If occupied, offer swap or move the previous roll to Storage. Show the resulting assignment and an Undo action. Label this Assign to slot. Physical Load remains a separate printer operation.
  3. Update stock: choose measured net weight, gross weight with a known tare, or an estimate. Preview the result and evidence label. Unknown tare cannot produce a measured net amount. Retain the prior evidence and explain a conflicting newer edit without losing the draft.
  4. Find a roll: search names, material, finish, brand and ID. Filter Storage, Loaded, Low stock, Unknown amount and Archived; sort amount, color, material or name. Grouping is optional. A search with no results keeps a clear reset action.
  5. Receive a replacement: from a spent roll, open its purchase link or record a received replacement. Opening a shop changes no stock. Receiving creates a new physical ID in Storage, retaining the spent roll's history.
  6. Correct a mistake: reversible moves and edits have Undo. Archive replaces destructive delete. Restoring history is explicit. Undo checks for intervening changes before applying an inverse operation.

Data and implementation contracts

  • Physical roll ≠ product ≠ slicing profile ≠ AMS position. A brand-neutral product can have several physical rolls; each roll can move without losing its identity. The selected slicing profile must not rename the physical material.
  • One backend: preserve the canonical inventory and shared transaction path. Add a typed DTO carrying exact gram strings, nullable values, evidence, timestamps, revision and capabilities. Avoid deriving exact stock from displayed percentages.
  • Clear authority: an inventory slot assignment and observed printer telemetry are separate facts. A stale device report must not silently relocate or rename a roll. An explicit reconciliation flow can resolve disagreement.
  • Honest save status: Pending, Saved locally, Could not save and Changed elsewhere. Bambu cloud connection belongs in a separate optional connection panel. Show a recoverable message and retain user input on failure.
  • Durable history: use structured events or a journal for transactions and inverse edits, with idempotency keys. Preserve the existing ledger and exact values during migration; a revision/hash alone is not sufficient for reliable multi-step Undo.
  • Scoped components: SlotRack, RollList, RollDetails, AddRollForm, StockEditor and ActivityTimeline. Use existing React/TypeScript components and shared design tokens. Keep printer motion behind its existing explicit command flow.
  • Optional future core: a Rust inventory core can implement the same versioned contract later. The visual redesign and user workflows do not depend on rewriting the slicer or desktop shell.

Interaction and accessibility

Offer click-to-assign and labelled Move to controls first. Drag-and-drop can be added as a shortcut with equivalent click and keyboard controls. Details preserve list context. True modal forms support focus containment, Escape and return focus. Do not reset focus, selection or scroll on background updates. Follow W3C dragging alternatives and the dialog interaction pattern.

Acceptance scenarios

  1. Assign Bone to slot 1 in Studio; the widget shows the same physical roll and unchanged grams.
  2. Move a roll in the widget; Studio updates its slot and detail panel while preserving any unrelated draft.
  3. Keep a 0g roll, a small positive remainder, and an unknown amount visibly distinct in both clients.
  4. Disconnect Bambu cloud; local inventory remains editable. Disconnect the local backend; show failure and avoid acknowledging an unsaved change.
  5. Edit one roll in two clients; independent fields merge, conflicting fields show current/proposed values, and Undo cannot erase a newer change.
  6. Add or receive two identical rolls; they receive separate IDs and remain individually traceable through slots, history and archive.
  7. Import the current inventory; compare every exact gram string, capacity, physical ID, location and historical event. No new print debit or reset.
  8. Test 375, 414, 768, 1024 and 1440px widths; dark/light themes; 200% zoom; keyboard and supported WebKitGTK. Verify readable text, no page overflow and persistent focus.
  9. Exercise 11, 100 and 1000 sample rolls. Search and selection stay responsive; group/pagination changes preserve selection and do not reorder an open editor.
